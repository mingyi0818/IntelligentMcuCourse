第 8 章 中断系统

学习目标

  • 理解中断的基本概念、处理流程与中断源的分类
  • 掌握 MCS-51 中断系统结构，熟悉 IE/IP/TCON 寄存器的位定义与配置方法
  • 能够编写外部中断 INT0/INT1 的应用程序，实现按键触发等功能
  • 理解 2 级中断优先级与嵌套规则，掌握中断现场保护的方法
  • 能够分析中断响应时间，理解影响实时性的因素

8.1 中断概念与处理流程

中断（Interrupt）是 CPU 在执行程序过程中，遇到突发事件（如外部信号、定时器溢出、数据到达等）时，暂停当前程序、转去处理突发事件、处理完后再返回原程序继续执行的机制。中断是单片机实现实时响应的核心手段——没有中断，CPU 只能通过轮询（Polling）方式查询外设状态，效率低且无法及时响应。

中断处理涉及几个关键术语：中断源（产生中断请求的设备或事件）、中断请求（中断源发出的信号）、中断允许/屏蔽（CPU 是否响应该中断）、中断优先级（多个中断同时发生时的处理顺序）、中断服务程序（ISR，Interrupt Service Routine，处理中断的程序）、中断返回（IRET，从中断返回主程序）。

响应中断时，硬件自动完成三件事：①将当前 PC（下一条指令地址）压入堆栈保存断点；②将 PC 装载为对应中断源的入口地址（如 INT0 为 0003H）；③不自动关闭总中断（与某些 CPU 不同，8051 的 RETI 才恢复）。执行到 RETI 指令时，硬件自动弹出断点地址到 PC，返回主程序。

8.2 MCS-51 中断系统结构

MCS-51 标准有 5 个中断源，STC 8位单片机扩展到 8 个（增加 T2 中断等）。5 个基本中断源对比如下：

中断源名称入口地址请求标志中断号触发方式
INT0外部中断 00003HIE0 (TCON.1)0低电平 / 下降沿（IT0 选择）
T0定时器 0 溢出000BHTF0 (TCON.5)1计数器溢出自动置位
INT1外部中断 10013HIE1 (TCON.3)2低电平 / 下降沿（IT1 选择）
T1定时器 1 溢出001BHTF1 (TCON.7)3计数器溢出自动置位
TI/RI串行口中断0023HTI/RI (SCON)4发送/接收完成

8.2.1 IE 中断允许寄存器

IE（Interrupt Enable，地址 A8H，可位寻址）控制各中断源的允许与否，位定义如下：

位符号功能
IE.7EA总中断允许。EA=1 开总中断，EA=0 关所有中断
IE.6—保留
IE.5ET2定时器 2 中断允许（STC）
IE.4ES串行口中断允许
IE.3ET1定时器 1 中断允许
IE.2EX1外部中断 1 允许
IE.1ET0定时器 0 中断允许
IE.0EX0外部中断 0 允许

必须同时置位 EA 和对应中断源的允许位，该中断才能被响应。例如允许外部中断 0：EA = 1; EX0 = 1;。

8.2.2 IP 中断优先级寄存器

IP（Interrupt Priority，地址 B8H，可位寻址）控制各中断源的优先级，位为 1 表示高优先级，为 0 表示低优先级：

位符号功能
IP.7~6—保留
IP.5PT2定时器 2 优先级（STC）
IP.4PS串行口优先级
IP.3PT1定时器 1 优先级
IP.2PX1外部中断 1 优先级
IP.1PT0定时器 0 优先级
IP.0PX0外部中断 0 优先级

8.2.3 TCON 定时器控制寄存器

TCON（地址 88H，可位寻址）既控制定时器启停，也包含外部中断的触发方式与标志位：

位符号功能
TCON.7TF1T1 溢出标志，硬件置位，中断响应后硬件自动清零
TCON.6TR1T1 运行控制，TR1=1 启动 T1
TCON.5TF0T0 溢出标志
TCON.4TR0T0 运行控制
TCON.3IE1INT1 请求标志，下降沿触发时中断响应后自动清零
TCON.2IT1INT1 触发方式：0=低电平触发，1=下降沿触发
TCON.1IE0INT0 请求标志
TCON.0IT0INT0 触发方式：0=低电平触发，1=下降沿触发
触发方式选择：电平触发下，中断响应后若外部仍为低电平会再次触发，适合电平型信号；下降沿触发只在边沿时刻触发一次，适合按键等脉冲型信号。实际应用中外部中断多用下降沿触发。

8.3 外部中断 INT0/INT1 应用

外部中断 INT0（P3.2）和 INT1（P3.3）是 MCS-51 与外部紧急事件交互的重要通道。典型应用包括按键紧急停止、旋转编码器计数、外部 ADC 转换完成信号等。本节通过"按键触发外部中断切换 LED"演示完整编程流程。

8.3.1 编程步骤

  1. 配置触发方式：写 IT0/IT1 选择电平或下降沿触发。
  2. 开中断允许：置位 EX0/EX1 和 EA。
  3. 编写中断服务函数：用 C51 的 interrupt 关键字声明，中断号 0（INT0）或 2（INT1）。
  4. 主程序初始化后进入主循环，等待中断发生。

8.3.2 完整示例

#include <reg52.h>

sbit LED1 = P1^0;        // 主 LED，主程序中流水灯
sbit LED2 = P1^4;        // 中断指示 LED
sbit KEY_INT0 = P3^2;    // INT0 按键

unsigned char flag_int = 0;   // 中断发生标志

void delay_ms(unsigned int ms) {
    unsigned int i, j;
    for (i = 0; i < ms; i++)
        for (j = 0; j < 110; j++);
}

// INT0 中断服务函数（中断号 0）
void int0_isr(void) interrupt 0 {
    LED2 = ~LED2;             // 翻转 LED2 指示中断发生
    flag_int = 1;             // 置标志，通知主程序
}

void main(void) {
    // 1. 配置 INT0 下降沿触发
    IT0 = 1;                  // IT0=1 下降沿触发
    // 2. 清除可能的中断标志
    IE0 = 0;
    // 3. 开中断
    EX0 = 1;                  // 允许 INT0
    EA  = 1;                  // 开总中断

    LED1 = 0xFE;
    while (1) {
        // 主程序：流水灯
        delay_ms(300);
        LED1 = (LED1 << 1) | 0x01;
        if (LED1 == 0xFF) LED1 = 0xFE;

        // 检查中断标志
        if (flag_int) {
            flag_int = 0;
            // 可在此处理中断后续逻辑
        }
    }
}

上述程序运行时，主程序持续执行流水灯；当按下 INT0 按键时，CPU 立即暂停流水灯，跳转到 int0_isr 翻转 LED2 并置标志，然后返回主程序继续流水灯。这种"主循环+中断"的结构是嵌入式系统的典型架构。

8.4 中断嵌套与优先级

MCS-51 支持 2 级中断优先级：高优先级和低优先级。优先级规则如下：

  • 低优先级中断正在执行时，若发生高优先级中断，则中断嵌套——高优先级中断打断低优先级中断，先执行高优先级 ISR，返回后再继续低优先级 ISR。
  • 高优先级中断正在执行时，任何中断都不能打断它（同级也不行）。
  • 同级中断之间不能嵌套，需等当前 ISR 执行完才能响应。
  • 同时发生多个同级中断时，按固定顺序查询：INT0 → T0 → INT1 → T1 → UART。

设置优先级的示例：将 INT1 设为高优先级，其余为低优先级：

void main(void) {
    IT0 = 1;  IT1 = 1;       // 下降沿触发
    PX1 = 1;                 // INT1 高优先级
    PX0 = 0;                 // INT0 低优先级
    EX0 = 1;  EX1 = 1;       // 允许中断
    EA  = 1;
    while (1);
}

8.5 中断函数的现场保护

中断发生时，CPU 暂停主程序转去执行 ISR。若 ISR 中修改了主程序正在使用的寄存器（如 A、PSW、R0~R7），返回主程序后这些寄存器的值已被破坏，会导致主程序出错。因此必须保护现场——在 ISR 开头保存这些寄存器，结尾恢复。

8.5.1 硬件自动保护

MCS-51 响应中断时硬件只自动保存 PC（断点地址），不保存 A、PSW 等寄存器。这与 ARM Cortex-M 自动保存 R0~R3、R12、LR、PC、xPSR 不同，8051 的现场保护需要软件完成。

8.5.2 软件保护：using 关键字

C51 编译器为中断函数提供两种现场保护方式：

  • 不写 using：编译器自动在 ISR 开头 PUSH ACC/PSW/B/DPH/DPL/R0~R7 等用到的工作寄存器，结尾 POP 恢复。代码体积大，但通用性好。
  • 写 using n：ISR 使用第 n 组工作寄存器（R0~R7），避免与主程序争夺，编译器无需 PUSH/POP R0~R7，代码体积小、速度快。但 n 必须与主程序使用的组不同。
// 方式一：不写 using，编译器自动保护（代码体积大）
void timer0_isr(void) interrupt 1 {
    TH0 = 0xFC;
    TL0 = 0x18;
    P1 = ~P1;
}

// 方式二：使用第 1 组寄存器（代码体积小）
void timer0_isr(void) interrupt 1 using 1 {
    TH0 = 0xFC;
    TL0 = 0x18;
    P1 = ~P1;
}
建议：对实时性要求高、频繁触发的中断（如高频定时器中断）建议用 using；对偶尔触发的中断（如按键外部中断）可不写 using，让编译器自动保护。注意同一工程中不同中断的 using 组号不能冲突。

8.6 中断响应时间分析

中断响应时间（Interrupt Latency）是从中断请求发出到 CPU 开始执行 ISR 第一条指令所经过的时间，是衡量实时性的关键指标。MCS-51 的中断响应时间分析如下：

MCS-51 在每个机器周期的 S5P2 采样中断请求，下一个机器周期开始响应。响应过程包括：①硬件查询中断（1 个机器周期）；②长调用 LCALL 到中断入口（2 个机器周期）；③若 ISR 开头有 LJMP 跳转到真正处理代码，再加 2 个机器周期。因此最短响应时间为 3 个机器周期。

但若中断请求发生时 CPU 正在执行多周期指令（如 MUL/DIV 占 4 周期），需等该指令执行完；若正在执行 RETI 或访问 IE/IP 的指令，需再执行完一条指令才能响应。因此最长响应时间为 8 个机器周期。响应时间范围：

$$T_{response} = (3 \sim 8) \times T_{machine} = (3 \sim 8) \times \frac{12}{f_{osc}}$$

以 11.0592MHz 晶振为例：

$$T_{response,min} = 3 \times \frac{12}{11.0592 \times 10^6} \approx 3.26 \, \mu s$$

$$T_{response,max} = 8 \times \frac{12}{11.0592 \times 10^6} \approx 8.68 \, \mu s$$

即 STC 在 11.0592MHz 下的中断响应时间约为 3.26~8.68 微秒。对于大多数控制应用，这个响应速度足够；但若需亚微秒级响应（如高速 PWM、精确脉冲测量），8051 较慢，应考虑 STM32 等高性能单片机。

晶振频率机器周期最短响应时间最长响应时间
11.0592 MHz1.085 μs3.26 μs8.68 μs
12 MHz1.000 μs3.00 μs8.00 μs
24 MHz0.500 μs1.50 μs4.00 μs
优化建议：①提高晶振频率可线性缩短响应时间；②ISR 尽量短小，把耗时逻辑放主程序处理；③对时间敏感的操作用下降沿触发而非电平触发，避免电平持续导致重复响应；④使用 using 关键字减少现场保护开销。

本章小结

  • 中断是 CPU 暂停当前程序、处理突发事件、再返回的机制，是实现实时响应的核心手段，优于轮询方式。
  • MCS-51 有 5 个基本中断源（INT0/T0/INT1/T1/UART），STC 扩展到 8 个；入口地址 0003H~0023H 固定分配。
  • IE 寄存器控制中断允许（EA 总开关 + 各源开关），IP 控制优先级（2 级），TCON 控制外部中断触发方式（IT0/IT1）与定时器标志。
  • 外部中断 INT0/INT1 可选低电平或下降沿触发，按键等脉冲信号多用下降沿触发。
  • 中断嵌套规则：高优先级可打断低优先级，同级不能嵌套；同时发生时按 INT0→T0→INT1→T1→UART 顺序查询。
  • 8051 只自动保存 PC，其他寄存器需软件保护；C51 的 using 关键字可指定 ISR 使用独立工作寄存器组，减少 PUSH/POP 开销。
  • 中断响应时间为 3~8 个机器周期，11.0592MHz 下约 3.26~8.68μs；提高晶振频率可线性缩短响应时间。
