第 42 章 OpenHarmony 智慧农业大棚（STM32F407+DHT11+继电器）

学习目标

  • 掌握基于 STM32F407（拓维 Niobe407）+ OpenHarmony LiteOS-M 的智慧农业大棚系统需求分析方法
  • 理解 CMSIS-OS2 标准接口（osThreadNew/osMessageQueueNew/osMutexAcquire）在多任务调度中的应用
  • 学会使用 HDF（Hardware Driver Foundation）GPIO 驱动框架控制 DHT11、继电器、光敏等外设
  • 掌握滞后控制（Hysteresis Control）策略在温室阈值控制中的工程实现，避免执行器频繁启停
  • 能独立完成"传感器采集—控制—显示—通信"四任务架构的工程构建、调试与扩展

§42.1 项目需求分析

§42.1.1 行业背景与应用场景

智慧农业是物联网技术在农业领域的典型应用，其中温室大棚因封闭环境可控、附加值高，成为智慧农业落地的首选场景。传统大棚依赖人工巡检与手动开关通风/灌溉设备，存在响应慢、能耗高、劳动强度大等问题。基于单片机+RTOS 的嵌入式控制系统可实现 7×24 小时无人值守，将温湿度、土壤湿度、光照强度等关键指标维持在作物最适区间，提升产量与品质。

本项目面向中小型设施农业（单棚面积 0.5~2 亩），目标是用一颗 STM32F407（拓维 Niobe407 开发板，OpenHarmony LiteOS-M 内核）完成多传感器采集、阈值控制、本地显示与远程上报的完整闭环，是第 40 章（智能照明）与第 41 章（分布式环境监测）技术的综合性应用。

§42.1.2 功能需求

系统需实现以下功能：

  • 环境采集：空气温湿度（DHT11，单总线）、土壤湿度（模拟电压，ADC 通道）、光照强度（光敏电阻，ADC 通道），采样周期 1 s。
  • 阈值控制：温度 >32 ℃ 开风扇降温；土壤湿度 <30% 开水泵灌溉；光照 <200 lux 开补光灯。所有控制采用滞后区间（Hysteresis Band）避免频繁启停。
  • 本地显示：0.96" OLED（I2C）实时显示 4 项参数与 3 路继电器状态，刷新周期 500 ms。
  • 远程上报：ESP8266 通过 AT 指令以 MQTT 协议每 10 s 上报一帧 JSON 数据到云端 Broker，支持远程下发控制命令。
  • 异常告警：温度 >38 ℃ 或传感器离线时蜂鸣器告警，并在 OLED 上显示 "!" 图标。

§42.1.3.2 滞后控制设计要点

提示：滞后控制（Hysteresis）是工程实践中的关键技巧。例如温度阈值设为 32 ℃ 开风扇、30 ℃ 关风扇，区间 2 ℃ 可避免在临界值附近继电器频繁吸合/断开，延长执行器寿命。本项目所有控制任务均采用 2%~5% 的滞后带。

§42.2 LiteOS-M 任务调度与 CMSIS-OS2 接口

§42.2.1 OpenHarmony LiteOS-M 内核简介

OpenHarmony LiteOS-M 是面向 MCU（Cortex-M 系列）的轻量级实时操作系统内核，提供任务调度、软件定时器、消息队列、信号量、互斥锁、事件标志等 RTOS 标准能力，ROM 占用 <10 KB，RAM 占用可低至 2 KB。它与 STM32F407 的 Cortex-M4 内核深度适配，是 OpenHarmony 在轻量设备上的标准内核。

本项目通过 CMSIS-OS2（Cortex Microcontroller Software Interface Standard - OS API v2）标准接口调用 LiteOS-M 内核服务。CMSIS-OS2 是 ARM 制定的 RTOS 抽象层，同一份应用代码可移植到 FreeRTOS、RT-Thread、LiteOS-M 等不同内核，是 OpenHarmony 推荐的 RTOS API。

§42.2.4 消息队列与互斥锁的协作

本项目中传感器采集任务每 1 s 产生一帧数据，控制任务每 5 s 消费一次。若直接共享全局变量，可能出现"控制任务读到一半时被采集任务覆盖"的竞态。解决方案是用 osMessageQueueNew 创建一个深度为 8 的环形队列，采集任务入队、控制任务出队；同时为 OLED、ESP8266 这类"非线程安全"的外设用 osMutex 串行化访问。

§42.3.2.2 优先级设计原则

优先级设计原则：采集 > 控制 > 显示 > 通信。采集任务优先级最高以保证数据实时性；通信任务优先级最低，避免网络重传阻塞影响实时控制。栈大小根据任务内局部变量与函数调用深度估算，ESP8266 AT 解析需较大缓冲区，故 CommTask 栈最大。

§42.5.2 数据结构与全局对象

定义统一的传感器数据结构体 SensorData_t，作为消息队列的消息单元。所有任务通过它传递数据，避免类型不一致问题。

/* sensor_data.h */
#ifndef __SENSOR_DATA_H
#define __SENSOR_DATA_H

#include <stdint.h>
#include "cmsis_os2.h"

/* 传感器数据帧 */
typedef struct {
    int16_t  temperature;  /* 温度 x10，单位 0.1 ℃，例如 252 表示 25.2 ℃ */
    uint16_t humidity;     /* 湿度，单位 % */
    uint16_t soil;         /* 土壤湿度，单位 %（ADC 标定后） */
    uint16_t light;        /* 光照强度，单位 lux（ADC 估算） */
    uint32_t timestamp;    /* LiteOS-M 软时钟，单位 tick */
} SensorData_t;

/* 执行器状态 */
typedef struct {
    uint8_t fan;     /* 0=关 1=开 风扇 */
    uint8_t pump;    /* 0=关 1=开 水泵 */
    uint8_t lamp;    /* 0=关 1=开 补光灯 */
    uint8_t alarm;   /* 0=正常 1=告警 */
} ActuatorState_t;

/* 全局共享对象（在 main.c 中定义） */
extern osMessageQueueId_t g_sensorQueue;   /* 传感器数据队列 */
extern osMutexId_t        g_oledMutex;     /* OLED 互斥锁 */
extern osMutexId_t        g_stateMutex;    /* 执行器状态互斥锁 */
extern SensorData_t       g_latestData;    /* 最新数据快照 */
extern ActuatorState_t    g_actuator;      /* 执行器状态 */

#endif

§42.5.3 主程序与任务创建

主程序完成 HDF 驱动初始化、互斥锁/消息队列创建、4 个任务创建，然后进入调度器。注意 OpenHarmony LiteOS-M 入口为 app_main，由系统启动流程调用。

/* main.c —— OpenHarmony LiteOS-M 应用入口 */
#include "ohos_init.h"
#include "cmsis_os2.h"
#include "sensor_data.h"
#include "sensor_task.h"
#include "control_task.h"
#include "display_task.h"
#include "comm_task.h"
#include "hdf_gpio.h"

/* 全局对象定义 */
osMessageQueueId_t g_sensorQueue;
osMutexId_t        g_oledMutex;
osMutexId_t        g_stateMutex;
SensorData_t       g_latestData;
ActuatorState_t    g_actuator = {0, 0, 0, 0};

/* 任务栈（静态分配，避免动态分配失败） */
static uint8_t sensor_stack[1024];
static uint8_t control_stack[1024];
static uint8_t display_stack[512];
static uint8_t comm_stack[2048];

static void SystemInit_Hardware(void)
{
    /* 1. HDF GPIO 初始化：继电器、蜂鸣器 */
    HdfGpioInit(0, HDF_GPIO_OUT);  /* PD0 风扇 */
    HdfGpioInit(1, HDF_GPIO_OUT);  /* PD1 水泵 */
    HdfGpioInit(2, HDF_GPIO_OUT);  /* PD2 补光灯 */
    HdfGpioInit(3, HDF_GPIO_OUT);  /* PD3 蜂鸣器 */
    HdfGpioWrite(0, 0);
    HdfGpioWrite(1, 0);
    HdfGpioWrite(2, 0);
    HdfGpioWrite(3, 0);

    /* 2. DHT11 单总线 GPIO（PE0） */
    HdfGpioInit(4, HDF_GPIO_OUT_OD);

    /* 3. ADC1 通道 0/1 初始化（土壤/光敏） */
    HdfAdcInit(0);

    /* 4. I2C1 OLED 初始化 */
    HdfI2cInit(0);

    /* 5. USART1 ESP8266 初始化 */
    HdfUartInit(1, 115200);
}

static void AppMain(void)
{
    osMutexAttr_t mutex_attr = {0};
    osMessageQueueAttr_t mq_attr = {0};

    /* 1. 硬件初始化 */
    SystemInit_Hardware();

    /* 2. 创建互斥锁 */
    g_oledMutex  = osMutexNew(&mutex_attr);
    g_stateMutex = osMutexNew(&mutex_attr);

    /* 3. 创建消息队列：深度 8，每条消息为 SensorData_t */
    g_sensorQueue = osMessageQueueNew(8, sizeof(SensorData_t), &mq_attr);
    if (g_sensorQueue == NULL) {
        /* 失败处理：点亮蜂鸣器告警 */
        HdfGpioWrite(3, 1);
        return;
    }

    /* 4. 创建 4 个任务 */
    osThreadAttr_t attr;
    attr.priority   = osPriorityNormal;
    attr.stack_mem  = NULL;

    attr.name       = "SensorTask";
    attr.priority   = osPriorityAboveNormal;   /* 优先级 5 */
    attr.stack_mem  = sensor_stack;
    attr.stack_size = sizeof(sensor_stack);
    osThreadNew(SensorTask, NULL, &attr);

    attr.name       = "ControlTask";
    attr.priority   = osPriorityNormal4;       /* 优先级 4 */
    attr.stack_mem  = control_stack;
    attr.stack_size = sizeof(control_stack);
    osThreadNew(ControlTask, NULL, &attr);

    attr.name       = "DisplayTask";
    attr.priority   = osPriorityNormal3;       /* 优先级 3 */
    attr.stack_mem  = display_stack;
    attr.stack_size = sizeof(display_stack);
    osThreadNew(DisplayTask, NULL, &attr);

    attr.name       = "CommTask";
    attr.priority   = osPriorityBelowNormal;   /* 优先级 2 */
    attr.stack_mem  = comm_stack;
    attr.stack_size = sizeof(comm_stack);
    osThreadNew(CommTask, NULL, &attr);

    /* 5. 调度器已由 LiteOS-M 启动，无需手动 osKernelStart */
}

/* OpenHarmony 启动钩子 */
APP_FEATURE_INIT(AppMain);

§42.5.4 传感器采集任务

采集任务每 1 s 唤醒一次，依次读取 DHT11、ADC 土壤、ADC 光敏，组帧后入队。若 DHT11 校验失败则丢弃本次数据并重试 2 次。

/* sensor_task.c */
#include "sensor_task.h"
#include "sensor_data.h"
#include "cmsis_os2.h"
#include "hdf_gpio.h"
#include "hdf_adc.h"
#include "dht11.h"
#include <string.h>

#define SENSOR_PERIOD_MS   1000
#define DHT11_RETRY        2

void SensorTask(void *arg)
{
    (void)arg;
    SensorData_t data;
    Dht11Result dht;
    uint16_t adc_soil, adc_light;
    osStatus_t status;
    uint8_t retry;

    memset(&data, 0, sizeof(data));

    for (;;) {
        /* 1. 读 DHT11，最多重试 2 次 */
        retry = 0;
        do {
            if (Dht11_Read(4, &dht) == 0) break;   /* 0=成功 */
            retry++;
            osDelay(20);
        } while (retry < DHT11_RETRY);

        if (retry < DHT11_RETRY) {
            data.temperature = (int16_t)(dht.temp * 10);   /* x10 */
            data.humidity    = dht.humi;
        } else {
            data.temperature = -999;  /* 错误码 */
            data.humidity    = 0;
        }

        /* 2. 读土壤湿度（ADC 通道 0），线性映射到 0~100% */
        HdfAdcRead(0, &adc_soil);
        /* 干土 ~3300，湿土 ~800，反向映射 */
        if (adc_soil > 3300) adc_soil = 3300;
        if (adc_soil < 800)  adc_soil = 800;
        data.soil = (uint16_t)(100 - (uint32_t)(adc_soil - 800) * 100 / 2500);

        /* 3. 读光照（ADC 通道 1），近似估算 lux */
        HdfAdcRead(1, &adc_light);
        /* 0~4095 → 0~20000 lux（粗略线性） */
        data.light = (uint16_t)((uint32_t)adc_light * 20000 / 4095);

        /* 4. 时间戳 */
        data.timestamp = osKernelGetTickCount();

        /* 5. 入队（覆盖最老数据：try without wait） */
        status = osMessageQueuePut(g_sensorQueue, &data, 0U, 0U);
        if (status == osErrorResource) {
            /* 队列满，弹出最老一条再入队 */
            SensorData_t old;
            osMessageQueueGet(g_sensorQueue, &old, NULL, 0U);
            osMessageQueuePut(g_sensorQueue, &data, 0U, 0U);
        }

        /* 6. 同时更新最新数据快照（加锁） */
        osMutexAcquire(g_stateMutex, osWaitForever);
        memcpy(&g_latestData, &data, sizeof(data));
        osMutexRelease(g_stateMutex);

        /* 7. 周期延时 1 s */
        osDelay(SENSOR_PERIOD_MS);
    }
}

§42.5.5 控制任务（滞后控制）

控制任务每 5 s 出队一帧数据，根据阈值表执行滞后控制。滞后带（Hysteresis Band）的含义：上限触发开启，下限触发关闭，区间内保持原状态。

/* control_task.c */
#include "control_task.h"
#include "sensor_data.h"
#include "cmsis_os2.h"
#include "hdf_gpio.h"

/* 阈值定义：上限/下限（滞后带） */
#define TEMP_ON        320     /* 32.0 ℃ 开风扇 */
#define TEMP_OFF       300     /* 30.0 ℃ 关风扇 */
#define SOIL_ON        30      /* 土壤湿度 30% 开水泵 */
#define SOIL_OFF       45      /* 土壤湿度 45% 关水泵 */
#define LIGHT_ON       200     /* 光照 <200 lux 开补光灯 */
#define LIGHT_OFF      500     /* 光照 >500 lux 关补光灯 */
#define TEMP_ALARM     380     /* 38.0 ℃ 告警 */

#define CONTROL_PERIOD_MS  5000

void ControlTask(void *arg)
{
    (void)arg;
    SensorData_t data;
    ActuatorState_t local;
    osStatus_t status;

    for (;;) {
        /* 1. 等待消息，最多阻塞 5 s */
        status = osMessageQueueGet(g_sensorQueue, &data, NULL, CONTROL_PERIOD_MS);
        if (status != osOK) {
            /* 超时无数据，传感器可能离线 */
            osMutexAcquire(g_stateMutex, osWaitForever);
            g_actuator.alarm = 1;
            osMutexRelease(g_stateMutex);
            continue;
        }

        /* 2. 取当前执行器状态快照 */
        osMutexAcquire(g_stateMutex, osWaitForever);
        local = g_actuator;
        osMutexRelease(g_stateMutex);

        /* 3. 温度控制：滞后 */
        if (data.temperature >= TEMP_ALARM) {
            local.alarm = 1;
        } else if (data.temperature < TEMP_ALARM - 20) {
            local.alarm = 0;
        }

        if (data.temperature >= TEMP_ON) {
            local.fan = 1;
        } else if (data.temperature <= TEMP_OFF) {
            local.fan = 0;
        }
        /* 区间 (TEMP_OFF, TEMP_ON) 保持原状态 */

        /* 4. 土壤湿度控制：滞后 */
        if (data.soil <= SOIL_ON) {
            local.pump = 1;
        } else if (data.soil >= SOIL_OFF) {
            local.pump = 0;
        }

        /* 5. 光照控制：滞后 */
        if (data.light <= LIGHT_ON) {
            local.lamp = 1;
        } else if (data.light >= LIGHT_OFF) {
            local.lamp = 0;
        }

        /* 6. 写继电器 GPIO */
        HdfGpioWrite(0, local.fan);
        HdfGpioWrite(1, local.pump);
        HdfGpioWrite(2, local.lamp);
        HdfGpioWrite(3, local.alarm);

        /* 7. 回写共享状态 */
        osMutexAcquire(g_stateMutex, osWaitForever);
        g_actuator = local;
        osMutexRelease(g_stateMutex);
    }
}

§42.5.6 显示任务

显示任务每 500 ms 刷新 OLED。访问 I2C 总线前必须获取 g_oledMutex，避免与可能的远程命令解析任务竞争。

/* display_task.c */
#include "display_task.h"
#include "sensor_data.h"
#include "cmsis_os2.h"
#include "ssd1306.h"
#include <stdio.h>

#define DISPLAY_PERIOD_MS  500

void DisplayTask(void *arg)
{
    (void)arg;
    SensorData_t data;
    ActuatorState_t act;
    char line[24];

    for (;;) {
        /* 1. 取共享快照（加锁，时间 < 100us） */
        osMutexAcquire(g_stateMutex, osWaitForever);
        data = g_latestData;
        act  = g_actuator;
        osMutexRelease(g_stateMutex);

        /* 2. 获取 OLED 互斥锁 */
        osMutexAcquire(g_oledMutex, osWaitForever);

        SSD1306_Clear();
        /* 第一行：温度 */
        snprintf(line, sizeof(line), "T:%2d.%dC H:%3d%%",
                 data.temperature / 10,
                 (data.temperature >= 0 ? data.temperature : -data.temperature) % 10,
                 data.humidity);
        SSD1306_ShowStr(0, 0, line, 16);

        /* 第二行：土壤湿度 */
        snprintf(line, sizeof(line), "Soil:%3d%%", data.soil);
        SSD1306_ShowStr(0, 2, line, 16);

        /* 第三行：光照 */
        snprintf(line, sizeof(line), "Light:%5dlux", data.light);
        SSD1306_ShowStr(0, 4, line, 16);

        /* 第四行：执行器状态 */
        snprintf(line, sizeof(line), "F%d P%d L%d %s",
                 act.fan, act.pump, act.lamp,
                 act.alarm ? "!" : " ");
        SSD1306_ShowStr(0, 6, line, 16);

        SSD1306_Refresh();
        osMutexRelease(g_oledMutex);

        osDelay(DISPLAY_PERIOD_MS);
    }
}

§42.5.7 通信任务

通信任务每 10 s 组一帧 JSON 数据并通过 ESP8266 AT 指令 MQTT 发布到云端。组帧时使用 snprintf 避免缓冲区溢出。

/* comm_task.c */
#include "comm_task.h"
#include "sensor_data.h"
#include "cmsis_os2.h"
#include "esp8266_at.h"
#include <stdio.h>

#define COMM_PERIOD_MS   10000
#define JSON_BUF_LEN     128

void CommTask(void *arg)
{
    (void)arg;
    SensorData_t data;
    ActuatorState_t act;
    char json[JSON_BUF_LEN];
    int len;

    /* ESP8266 初始化 + 连接 AP + MQTT 服务器 */
    Esp8266_Reset();
    Esp8266_ConnectAp("GreenHouse_AP", "12345678");
    Esp8266_MqttConnect("broker.example.com", 1883,
                        "device_001", "user", "pass");

    for (;;) {
        /* 1. 取共享快照 */
        osMutexAcquire(g_stateMutex, osWaitForever);
        data = g_latestData;
        act  = g_actuator;
        osMutexRelease(g_stateMutex);

        /* 2. 组 JSON 帧 */
        len = snprintf(json, sizeof(json),
            "{\"t\":%d.%d,\"h\":%d,\"soil\":%d,\"lux\":%d,"
            "\"fan\":%d,\"pump\":%d,\"lamp\":%d,\"al\":%d}",
            data.temperature / 10,
            (data.temperature >= 0 ? data.temperature : -data.temperature) % 10,
            data.humidity, data.soil, data.light,
            act.fan, act.pump, act.lamp, act.alarm);

        /* 3. MQTT 发布 */
        if (len > 0 && len < (int)sizeof(json)) {
            Esp8266_MqttPublish("farm/device_001/data", json, len);
        }

        /* 4. 检查下行命令（非阻塞） */
        Esp8266_MqttPoll(0);

        osDelay(COMM_PERIOD_MS);
    }
}

§42.5.8 DHT11 单总线驱动

DHT11 使用单总线协议，主机拉低 18 ms 后释放，传感器响应 80 us 低 + 80 us 高，随后按位发送 40 bit 数据。以下驱动基于 HDF GPIO 实现：

/* dht11.c */
#include "dht11.h"
#include "hdf_gpio.h"
#include "cmsis_os2.h"

/* 单总线时序精度要求高，关闭中断读取 */
static void Dht11_ReadBit(uint8_t gpio, uint8_t *buf, uint8_t len)
{
    uint8_t i, j;
    uint8_t val;
    for (i = 0; i < len; i++) {
        /* 等待低电平结束（50us 前导） */
        uint32_t timeout = 1000;
        while (HdfGpioRead(gpio) == 0 && timeout--) ;
        /* 等待高电平：26us 表示 0，70us 表示 1 */
        uint32_t t = 0;
        while (HdfGpioRead(gpio) == 1 && t < 100) {
            HdfDelayUs(1);
            t++;
        }
        val = (t > 30) ? 1 : 0;
        buf[i / 8] = (buf[i / 8] << 1) | val;
    }
}

int Dht11_Read(uint8_t gpio, Dht11Result *out)
{
    uint8_t data[5] = {0};
    uint8_t i;

    /* 1. 主机发起：拉低 18ms */
    HdfGpioSetDir(gpio, HDF_GPIO_OUT_OD);
    HdfGpioWrite(gpio, 0);
    HdfDelayMs(18);
    HdfGpioWrite(gpio, 1);
    HdfDelayUs(30);

    /* 2. 切换输入 */
    HdfGpioSetDir(gpio, HDF_GPIO_IN_PULLUP);

    /* 3. 等待传感器响应（80us 低 + 80us 高） */
    uint32_t timeout = 1000;
    while (HdfGpioRead(gpio) == 0 && timeout--) ;
    if (timeout == 0) return -1;
    timeout = 1000;
    while (HdfGpioRead(gpio) == 1 && timeout--) ;
    if (timeout == 0) return -2;

    /* 4. 读 40 位 */
    Dht11_ReadBit(gpio, data, 40);

    /* 5. 校验和 */
    uint8_t sum = data[0] + data[1] + data[2] + data[3];
    if (sum != data[4]) return -3;

    /* DHT11 整数部分直接使用 */
    out->humi = data[0];
    out->temp = (int8_t)data[2];
    return 0;
}

§42.6.3 任务调试技巧

  • 任务状态查看：通过 LiteOS-M 提供的 osKernelGetThreadList 或加打印输出每个任务的 state、priority、stack_space。栈剩余空间 < 20% 时应增大栈。
  • 栈溢出检查：LiteOS-M 默认开启栈水位线（Stack Watermark）填充 0xC2C2C2C2。任务切换时检查栈底 magic word，若被覆盖则触发 LOS_TaskSwitchHook 钩子，可在钩子中打印任务名并重启。
  • printf 重定向：将 fputc 重定向到 USART2（PA2/PA3），与 ESP8266 占用的 USART1 隔离，避免调试输出干扰 AT 指令。
  • CPU 占用率：在 IDLE 任务中累计空闲计数，每 10 s 打印各任务 CPU 占用比。本项目实测：SensorTask 1%、ControlTask 0.5%、DisplayTask 5%（OLED I2C 较慢）、CommTask 0.2%、IDLE 93%。
提示：OLED 显示任务占 5% CPU 主要因 SSD1306 I2C 100 kHz 速率下整屏刷新耗时 ~30 ms。优化方案：(1) 改用 I2C 400 kHz Fast Mode；(2) 只刷新变化行（脏页机制）；(3) 把整屏刷新放到 DMA I2C 传输，主任务不阻塞。

§42.7 扩展方向

§42.7.1 PID 精确控制

本项目采用简单滞后控制，适用于执行器为"开关量"的场景。若改用 PWM 调速风扇、PWM 调光补光灯，可实现连续 PID 控制。温度控制离散 PID 公式：

u(k) = Kp·e(k) + Ki·Σe(i) + Kd·(e(k) − e(k−1))

其中 e(k) = T_set − T(k)。PID 参数可用 Ziegler-Nichols 法整定，本项目实测 Kp=2.0、Ki=0.1、Kd=0.5 可使温度稳定在 ±0.5 ℃ 区间。

§42.7.2 边缘机器学习

利用 STM32F407 的 Cortex-M4F 浮点单元和 CMSIS-NN 库，可在本地部署轻量级神经网络。例如基于历史温湿度序列预测未来 1 小时温度趋势，提前启动通风；或基于摄像头（OV2640）+ 轻量 CNN 识别叶片病虫害。OpenHarmony 提供 AI 子系统 mindspore-lite，支持 INT8 量化模型推理。

§42.7.3 多大棚联动

OpenHarmony 分布式软总线（SoftBus）可使多个大棚节点自组网。主节点聚合各分棚数据，统一上报云端，并支持跨棚联动（如 1 号棚温度过高时借用 2 号棚通风能力）。分布式软总线基于 WiFi 或 BLE，使用 CoAP 协议发现设备、TCP 传输数据。

§42.7.4 云端数据可视化与告警

云端可采用 EMQX + InfluxDB + Grafana 经典物联网栈：EMQX 作为 MQTT Broker，InfluxDB 时序存储，Grafana 可视化。配合钉钉/微信机器人推送告警，实现"采集—控制—可视化—告警"全链路。

§42.7.5 节能与低功耗

若改用电池供电，可利用 LiteOS-M 的 Tickless 模式：在所有任务阻塞时停止系统 tick，由低功耗定时器唤醒。STM32F407 进入 Stop 模式功耗可降至 ~0.5 mA，配合传感器间歇采样（如 1 min 一次），单节 18650 电池可工作数月。

本章小结

  • 智慧农业大棚是 OpenHarmony LiteOS-M 多任务调度的典型场景，按"采集—控制—显示—通信"四类职责划分任务，通过消息队列解耦、互斥锁串行化共享资源。
  • CMSIS-OS2 是 ARM 推荐的 RTOS 抽象层，osThreadNew、osMessageQueueNew、osMutexAcquire 三个核心 API 即可覆盖大部分多任务工程需求。
  • HDF（Hardware Driver Foundation）是 OpenHarmony 的统一驱动框架，将 GPIO/ADC/I2C/UART 抽象为标准接口，便于跨芯片移植。
  • 滞后控制（Hysteresis Control）是工程实践中避免执行器频繁启停的关键技巧，所有阈值控制都应设置 2%~5% 的滞后带。
  • 任务优先级设计遵循"采集 > 控制 > 显示 > 通信"原则，栈大小需根据局部变量与调用深度估算，建议保留 20% 余量并开启栈溢出检查。
  • 项目可扩展至 PID 精确控制、边缘 AI、多大棚联动、云端可视化等方向，是 OpenHarmony 在垂直行业落地的代表案例。

  2. 滞后控制的"上限触发开启、下限触发关闭"为何能避免继电器频繁启停？若滞后带设得过宽（如温度 25~35 ℃）会带来什么问题？
